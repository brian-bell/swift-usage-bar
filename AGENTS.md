## What this project is

**AIUsageBar** is a native macOS menu bar app (SwiftUI `MenuBarExtra`) that displays **percent remaining** for Claude (5-hour and weekly), ChatGPT/Codex (weekly only), and OpenCode Go (rolling 5-hour plus optional weekly and monthly). OpenCode Go is hidden by default. The menu bar label renders visible providers in at most two rows (`Cl`, `Cx`, `Go`); with three providers it partitions contiguous provider segments to minimize the widest row while preserving order. OpenCode Go renders `Go 88/74/92`, using `--` for unavailable optional windows. A `~` prefix marks stale data, a lone provider uses one large row, and `AI Usage` is shown when all providers are hidden. The dropdown shows per-window progress bars and reset countdowns, with distinct OpenCode session-expiry and workspace-selection guidance. Settings live in the standard macOS Settings window (`Settings` scene, ⌘,) and use staged OK/Cancel edits. Its Providers tab shows, per provider, a one-line data-source status and an expandable numbered retrieval chain with a recovery callout while stale; OpenCode Go's optional workspace ID/URL field lives inside that disclosure, and no pane ever exposes a cookie or token field.

Data access is strictly **read-only**: the app borrows existing local state and never writes to credential stores or refreshes OAuth tokens. The one narrow exception is that, only when the primary Codex credential is unavailable, AIUsageBar may invoke OpenAI's signed Codex desktop `app-server` for the read-only `account/rateLimits/read` RPC; that helper owns its own authentication lifecycle. AIUsageBar still never reads, logs, persists, refreshes, or writes Codex credentials, and it never invokes login, logout, turn, tool, or other mutation RPCs. When data can't be fetched, providers degrade to a greyed "stale" state instead of erroring.

- **Claude (first attempt — claude.ai web cookie)**: when wired (it is, in `.live()`), `ClaudeUsageProvider` tries a claude.ai browser-cookie path *before* the OAuth API below, because a browser session outlives the OAuth token (~30 days vs <24 h) and so yields fresh data on machines with no recent Claude Code activity. `ChromeClaudeWebSessionReader` reads Chrome's read-only `sessionKey` cookie for the exact `claude.ai` host (decrypted with the same Safe Storage secret and Chromium `v10`/`v11` AES-CBC scheme as OpenCode Go; the generalized `ChromeCookieDecryptor` strips the Chrome-130+ SHA-256 host prefix using candidate hosts `.claude.ai`/`claude.ai`), forwarding `lastActiveOrg`, `cf_clearance`, and `__cf_bm` alongside it; Safe Storage is only read when a `sessionKey` cookie exists, and the same `.background`/`.interactive` UI-suppression gate applies. `ClaudeWebHTTPTransport` (a dedicated ephemeral session with a redirect guard that refuses host-changing hops) resolves the org from the `lastActiveOrg` cookie and verifies it with `GET https://claude.ai/api/organizations/<org>/usage`; a 404 triggers `GET /api/bootstrap` discovery, selecting the membership whose capabilities include `claude_max`/`chat`. The usage response is **the same schema as the OAuth endpoint**, so `ClaudeUsageParser` is reused verbatim. Cloudflare fronts the endpoint and binds `cf_clearance` to the exact User-Agent that solved its challenge, so the transport sends a Chrome-shaped UA built from the installed Chrome version (`CFBundleShortVersionString`, else a recent fallback) plus `Origin`/`Referer`/`Sec-Fetch-*` headers. **Every** web-path failure — no cookie, Cloudflare 403/`Just a moment...`, expired session, unparseable body — falls back **silently** to the OAuth path (then the statusline cache) and never surfaces its own stale reason. It is strictly read-only: the cookie is never persisted, logged, refreshed, or modified. Because `cf_clearance`/`__cf_bm` are refreshed by real browsing, this path degrades to fallback whenever Chrome hasn't visited claude.ai recently — by design.
- **Claude (second attempt — OAuth usage API)**: **runs for every fetch, background and interactive** — the mode difference lives in the Keychain read: a `.background` read suppresses **both** legacy prompts this item can raise, so an automatic poll never presents a Keychain dialog and only a manual Refresh-now can. The two prompts need different guards: `kSecUseAuthenticationUIFail` on the query suppresses the trusted-application **ACL** prompt, but it does **not** suppress the **partition-id** password prompt (verified empirically, Jul 2026) — that one appears whenever the app's Team ID is missing from the item's partition list, which happens on a treadmill because Claude Code refreshes its token by shelling out to `/usr/bin/security`, whose write resets the partition list to `apple-tool:` and drops the `teamid:` entry a prior "Always Allow" had added. The partition prompt is suppressed only by disabling legacy-Keychain UI process-wide via `SecKeychainSetUserInteractionAllowed(false)` around the background read, which makes the blocked read fail fast (`errSecAuthFailed`) and degrade silently to the statusline cache / file fallback. `.interactive` (Refresh-now) re-enables UI so the user can act. It reads Claude Code's OAuth credential from the macOS Keychain (service `Claude Code-credentials`, matched by service only — the account attribute is omitted), falling back read-only to `${CLAUDE_CONFIG_DIR:-~/.claude}/.credentials.json` when the Keychain can't produce a usable credential (some Claude Code 2.1.x versions keep only `mcpOAuth` state in the Keychain item and the real credential in that file; an empty `CLAUDE_CONFIG_DIR` counts as unset). A *present* file's verdict wins over the Keychain's stale reason; an absent or unreadable file keeps the Keychain's reason, so keychain-only machines behave exactly as before. Either source decodes `claudeAiOauth.accessToken` + `expiresAt` (epoch **milliseconds**), and the app calls `GET https://api.anthropic.com/api/oauth/usage` with `Authorization: Bearer` and `anthropic-beta: oauth-2025-04-20`. An expired token short-circuits with no network call. The response's `five_hour`/`seven_day` `utilization` floats are percent used; `resets_at` is ISO 8601 with 6-digit fractional seconds (the parser normalizes fraction lengths `ISO8601DateFormatter` can't handle). A window that saw no recent usage lapses to an explicit `null` (e.g. `five_hour` after an idle night): the parser treats a null or missing window as 100% remaining with an unknown reset, but a body with neither window key (an error payload, `{}`) still fails as a parse failure. The parser also surfaces the model-scoped **Fable** weekly window when present — the entry in the response's `limits` array whose `scope.model.display_name` is `Fable` (its `percent` is percent used) — as an optional third window shown under Claude in the dropdown only (not the menu bar title, tone, or threshold notifications); a Fable entry with an unparseable/absent `resets_at` still renders with an unknown reset rather than being dropped. The app never refreshes the token — a machine with no recent Claude Code activity degrades to `.tokenExpired` stale by design (tokens live < 24 h).
- **Claude (fallback — statusline cache)**: Claude Code's statusline JSON in a local cache file (`${XDG_CACHE_HOME:-~/.cache}/ai-usage-bar/claude-status.json`, overridable via `AI_USAGE_BAR_CLAUDE_STATUS_JSON`) is the fallback whenever the API path can't produce fresh data (silently denied background Keychain read, expired token, network error, parse failure): a fresh cache still yields fresh data, and when both paths fail the API's failure reason is surfaced with the best available last-known usage (cache's over the caller's). The cache is written by `scripts/claude-statusline-cache`, a passthrough wrapper the user configures as their Claude Code statusline command (it tees stdin to the cache, then forwards to `ccstatusline`). Because multiple concurrent Claude Code sessions all run the wrapper — and idle sessions keep re-rendering with rate limits from their last API response — the wrapper only overwrites the cache when the incoming payload is at least as fresh, compared lexicographically on (weekly resets_at, weekly used, five-hour resets_at, five-hour used). That veto is scoped to a cache younger than `AI_USAGE_BAR_CACHE_MAX_AGE_SECONDS` (default 360 s, the app's own staleness bound; a malformed value falls back to the default): weekly `used_percentage` is *not* monotonic within a reset cycle (observed live: 46% → 26% under the same weekly resets_at), so without the age cutoff the compare pins the cache at a cycle's high-water mark indefinitely — an aged cache accepts any usable live payload, "older"-looking or not. The compare-and-replace runs under an exclusive `flock` on `claude-status.json.lock` (a persistent empty file next to the cache) so concurrent writers can't race the decision; if the guard itself can't run it falls open to writing, except that a payload without usable rate limits never replaces one with them. Both `used_percentage` and `resets_at` are accepted as int or float (Claude Code emits float percentages like `7.000000000000001`; the Swift decoder rounds to whole percent). On startup the wrapper reaps its own temp files older than an hour — strands left behind when a render is SIGKILLed (e.g. a statusline timeout). Cache older than 3× the poll interval is treated as stale. Because reading the cache never touches the network, `ClaudeStatuslineCacheReader` narrows its stale reason to what can actually go wrong locally — `.credentialUnavailable` (no cache file), `.parseFailure` (unusable contents), `.networkError` reserved for "parsed but older than `maximumAge`" — which the retrieval-chain UI phrases per source; a thrown read maps to `.credentialUnavailable`. Like the web path, the cache's reason is display-only: the surfaced `StaleReason` stays the API's.
- **Codex (primary)**: reads the Codex CLI credential from the macOS Keychain (service `Codex Auth`, account `cli|<first 8 bytes of sha256(canonical CODEX_HOME) as hex>`), checks JWT `exp` for expiry (expired token → no network call), then calls `GET https://chatgpt.com/backend-api/wham/usage` with the bearer token. This path and all of its existing failure semantics remain unchanged. Codex is weekly-only in the UI (`ProviderUsage.fiveHour` is always unavailable so the menu bar shows a single number `Cx 90` and the dropdown omits the 5h row). The weekly value is taken from `rate_limit.secondary_window` when present (legacy shape where primary was 5h), else from `primary_window` only when `limit_window_seconds == 604800` (live shape as of Jul 2026: weekly moved into primary, secondary null). A 5h-only primary (`18000`) or both windows null/absent is a parse failure.
- **Codex (desktop app-server fallback)**: is attempted **only** when the primary credential read returns `.credentialUnavailable`; an absent CLI Keychain item and a throwing credential reader both map to that reason. It is never attempted for an actually expired credential (`.tokenExpired`), `.parseFailure`, an authenticated HTTP failure, a response parse failure, or a transport/network failure. `CodexDesktopHelperDiscovery` asks `NSWorkspace` for bundle id `com.openai.codex`, appends `Contents/Resources/codex`, resolves symlinks and rejects paths outside the bundle, requires an executable with a valid code signature and OpenAI Team Identifier `2DC432GLL2`, and never searches `PATH`. `CodexAppServerUsageReader` lazily launches only that helper with `--sandbox read-only --ask-for-approval untrusted app-server --stdio`, performs JSON-RPC `initialize` (AIUsageBar metadata), `initialized`, then only `account/rateLimits/read`; it bounds lines and timeouts, matches response ids while ignoring notifications, reuses one actor-owned child, and terminates it on EOF, timeout, failure, poller stop, and app shutdown. Poller stop is reusable—a later start may relaunch a fresh helper—while final app shutdown permanently rejects late reads so quitting cannot orphan a child. The parser prefers `rateLimitsByLimitId["codex"]`, otherwise `rateLimits`, accepts a weekly window only when `windowDurationMins == 10080` plus the documented legacy secondary-window/missing-duration shape, and never mistakes 5-hour, 15-minute, or unknown primary windows for weekly. On success the source is `.codexAppServer`; if it fails, its reason stays display-only in the retrieval chain while the provider preserves previous usage and surfaces the original `.credentialUnavailable`.
- **OpenCode Go**: reads only Chrome's `auth` or `__Host-auth` cookie for the exact `opencode.ai` host. Chrome Safe Storage access is mode-sensitive: background reads disable legacy Keychain UI process-wide and use `kSecUseAuthenticationUIFail`, while only user-initiated refreshes may prompt. The cookie is decrypted in memory, filtered before transport, and is never persisted, logged, refreshed, or modified. A configured `wrk_…` workspace override skips discovery; otherwise the provider calls the captured private `_server` workspace function, probes all candidates with bounded concurrency, and automatically selects the sole page containing a valid rolling Go window. Zero candidates degrade to `.credentialUnavailable`; multiple candidates use `.workspaceSelectionRequired`. The dedicated ephemeral transport accepts only exact-host HTTPS requests, manually attaches the single cookie, rejects host-changing redirects, and maps authentication redirects/login HTML to `.sessionExpired`. The fixture-backed Seroval parser requires `rollingUsage`, accepts optional `weeklyUsage`/`monthlyUsage`, converts percent used to remaining, and derives every reset from one injected response-time clock.

## Build, test, run

There is no Makefile or CI config; SwiftPM and shell scripts are the whole build system. Toolchain: Swift 6 (6.3.3 via full Xcode 26.6, selected with `xcode-select`; the project was CommandLineTools-only until July 2026), target macOS 14+.

|---|---|
| `swift build` | Debug build; must be clean under Swift 6 strict concurrency |
| `swift test --enable-swift-testing` | Build **and execute** the Swift Testing suites (needs full Xcode selected; see note below) |
| `scripts/run-swift-tests` | Full harness: build + execute tests, failing if the toolchain compiled the suites without actually running them |
| `scripts/bundle.sh` | Release build → assemble `AIUsageBar.app` → codesign (ad-hoc, or `CODESIGN_IDENTITY`) → verify |
| `scripts/bundle.sh --verify [APP_PATH]` | Verify an existing bundle (plist keys, executable, signature) |
| `Tests/Scripts/bundle-script-test.sh` | Shell tests for the bundle script |
| `Tests/Scripts/claude-statusline-cache-test.sh` | Shell tests for the statusline cache wrapper |
| `scripts/setup-statusline` | Idempotently wire the cache wrapper into `statusLine` in Claude Code settings, preserving any existing statusline command in a passthrough shim |
| `Tests/Scripts/setup-statusline-test.sh` | Shell tests for the statusline setup script |
| `scripts/make-signing-cert` | Create + import a local CA-signed code-signing identity (stable designated requirement) for `CODESIGN_IDENTITY` |
| `Tests/Scripts/make-signing-cert-test.sh` | Shell tests for the signing-cert script (dry-run only, no keychain writes) |

Note: `Package.swift` carries `unsafeFlags` on the test targets pointing at `/Library/Developer/CommandLineTools/Library/Developer/Frameworks` because a CommandLineTools-only install exposes Swift Testing there but ships no `XCTest.framework`; the flags are harmless under full Xcode. Tests use Swift Testing (`@Test`/`#expect`), not XCTest.

**Test-execution note:** this machine has full Xcode selected (`xcode-select -p` → `/Applications/Xcode.app/Contents/Developer`), so `swift test --enable-swift-testing` genuinely executes the suites. On a CommandLineTools-only toolchain it compiles and links the test bundle but exits after `Build complete!` without executing anything (there is no runner to host the bundle) — `scripts/run-swift-tests` guards against that failure mode by requiring a `Test run with N tests` line in the output, and tells you to select full Xcode if it's missing. The first real execution of the suites (July 2026) surfaced 4 latent test failures, tracked (and fixed) via issue #17.

The app bundle is `AIUsageBar.app` (identifier `dev.brianbell.AIUsageBar`, `LSUIElement=true` so no Dock icon), signed for personal local use — no notarization or distribution. `bundle.sh` picks its signing identity in this order: an explicit `CODESIGN_IDENTITY`, else the first valid **"Apple Development"** identity in the keychain (preferred: its signature carries a genuine TeamIdentifier, so Keychain "Always Allow" grants record a stable `teamid:` partition entry and rebuilds stop prompting), else ad-hoc. A bad identity fails the signing step (`codesign signing failed for identity: …`) and the staging directory is cleaned up on any exit. When rebuilding or relaunching the user's login app, do not silently accept the ad-hoc fallback: run plain `scripts/bundle.sh` and verify with `codesign -dvvv AIUsageBar.app 2>&1` that `Signature=adhoc` is absent and a `TeamIdentifier` is set. Machines without an Apple Development identity can create a local one with `scripts/make-signing-cert` (set `CODESIGN_IDENTITY` to its name); that gives a stable designated requirement but no TeamIdentifier — macOS partition lists then pin each build's cdhash, costing one keychain prompt per provider per rebuild, and AMFI SIGKILLs any attempt to claim a team identifier without an Apple-issued chain (verified July 2026; do not re-attempt `--team-identifier`). `security find-identity -v -p codesigning` lists valid identities; treat the post-build `codesign -dvvv` output as authoritative.

## Key types and seams

All seams are protocols with injectable fakes; production adapters are thin leaves.

- `UsageWindow` / `ProviderUsage` / `ProviderState` (`.fresh` / `.stale(last:reason:)` / `.hidden`) — core domain. `ProviderUsage` has required five-hour/weekly slots plus optional monthly and Fable windows. Monthly participates in tone and threshold notifications; Fable remains Claude dropdown-only and is excluded from both. Providers never throw upward and preserve last-known usage on failure.
- `ProviderDataSource` / `ProviderDataSourceStep` / `ProviderFetchReport` — the *label* naming which retrieval path actually produced data (`claudeWebSession`, `claudeOAuthAPI`, `claudeStatuslineCache`, `codexAPI`, `codexAppServer`, `openCodeGoChromeCookie`), with a `displayName` for the one-line status and a `chainStepName` for the per-step chain UI. It is a label, never data: no credential, cookie, token, account id, or helper payload is ever carried, logged, or persisted. `ProviderID.dataSourceChain` declares each provider's sources in attempt order; Codex is `[.codexAPI, .codexAppServer]`. `ProviderFetchReport` pairs a `ProviderState` with the ordered `[ProviderDataSourceStep]` the fetch walked — each step an outcome of `used` / `standingBy` / `failed(StaleReason)` — and derives `source` as the `used` step (`nil` for every stale outcome). A provider reports only the steps it actually attempted; the view model pads the rest of the declared chain as `standingBy`. The report is carried *alongside* `ProviderState` rather than inside it so `ProviderState`'s pattern arity and `Equatable` semantics are unchanged — two states holding the same usage still compare equal regardless of which path fetched them. **A step's `failed` reason is display-only and must not be promoted to the surfaced `StaleReason`**: Claude's web and statusline-cache reasons stay inside their steps, and a failed Codex app-server fallback likewise leaves the surfaced reason as the primary path's `.credentialUnavailable` (tests pin both invariants).
- `ProviderStatusViewModel` — pure, unit-tested view model behind Settings › Providers. Each row is a one-line `State · method · age` (`Live · claude.ai web session · updated 2 min ago`, `Stale · Chrome session expired · last data 1 h ago`, `Off`) with a green/amber/grey dot, plus a `ProviderChainSection` rendered inside an expandable disclosure. A visible provider the poller hasn't reported on yet is a fourth state, `Checking…` with a grey dot — deliberately *not* amber `Stale`, since at launch the first poll is merely in flight and nothing has failed. The chain section holds numbered `ProviderChainStepRow`s (`Used 2 min ago` bold + green dot, `Standing by` muted, `Session expired · 1 h ago` bold + amber), an optional caption, a provider- and reason-specific recovery callout shown only while stale, and — for OpenCode Go only — the workspace field's label/placeholder/accessibility label and caption (which now live inside that disclosure rather than in the pane body). A failed step's phrase is chosen per *source*, not per `StaleReason` alone, so a step never blames a subsystem it doesn't use: the statusline cache is a local file, so its failures read `No cache file` (nothing written there / unreadable) and `Cache out of date` (parsed but older than the freshness bound) instead of `Network error`. `expandedProviders(remembering:)` is the tested decision behind auto-expanding stale providers on window open while remembering what the user opened by hand. `now` is injected so age formatting is deterministic. It feeds Settings only — the menu bar title, dropdown, tone, and threshold notifications are untouched by it.
- `UsageProvider` — `fetch(previous:mode:) async -> ProviderState` (with a `fetch(previous:)` convenience defaulting to `.background`), plus `fetchReport(previous:mode:) async -> ProviderFetchReport`, which the poller calls. `fetchReport` has a protocol-extension default returning the plain state with no chain, so test doubles need only implement `fetch`; the three real providers implement `fetchReport` as the real entry point and express `fetch` in terms of it so the two can't drift. `AppState` keeps the last winning source per provider (retained across a later failure) and the last reported chain (a *non-empty* chain always replaces the previous one, since a failing fetch's per-step reasons are exactly what the disclosure must show). Both are cleared when a *refresh result* reports `.hidden`; hiding through Settings retains them, exactly as it retains the provider's last state and usage (`appStateRestoresPreviousProviderStateAfterHideShow`), so an unhidden provider's row and its disclosure agree with each other. The Settings *preview* of a staged-on provider is the one place that must not use them: `providerStatusViewModel(stagedVisibility:)` drops the state, source, chain, and last-updated date of a provider staged back on, because that row reads `Checking…` and a retained green `Used 3 h ago` step underneath it would claim a source is producing data right now. Implementations: `ClaudeUsageProvider`, `CodexUsageProvider`, and `OpenCodeGoProvider`. Claude and the Codex primary path use the shared `HTTPTransport`; Codex optionally uses the narrow `CodexAppServerUsageReading` fallback boundary, and OpenCode Go uses its own locked-down transport and `OpenCodeSessionReading` seam.
- `CredentialAccessMode` (`.interactive` / `.background`) — threads poller → provider → credential reader → Keychain query. Background reads use both `kSecUseAuthenticationUIFail` and process-wide legacy-Keychain UI suppression so Claude, Codex, and Chrome Safe Storage fail quickly without prompting. Only `refreshNow()` uses `.interactive` and re-enables UI.
- `OpenCodeSessionReading` — a dedicated read-only Chrome session seam. Production scans Chrome `Default` / `Profile *` cookie databases read-only, selects only the exact OpenCode cookie, decrypts Chromium `v10`/`v11` AES-CBC values with the Safe Storage secret, and returns the in-memory `Cookie` header value. It has no write API.
- `CredentialStore` — read-only by design: the protocol exposes only `read(_:mode:) -> Data?` (plus a `read(_:)` convenience defaulting to `.background`). Two implementations: `KeychainCredentialStore` wraps `SecItemCopyMatching`, and `ClaudeCredentialsFileStore` reads `${CLAUDE_CONFIG_DIR:-~/.claude}/.credentials.json` (absent file → `nil`, unreadable → `.unavailable`; `mode` is ignored since file reads can't prompt) — wired as `ClaudeCredentialReader`'s `fallbackStore` in `.live()`. There are no write/delete calls anywhere, and tests enforce this. **Do not add a write surface.**
- `UsagePoller` (actor) — polls every 2 minutes by default (min 1 s), plus on wake (`AsyncStream<Void>` seam wired to `NSWorkspace.didWakeNotification`) and on manual refresh. Automatic polls (start/timer/wake) use `.background` credential access; `refreshNow()` uses `.interactive`, and a manual refresh that coalesces onto an in-flight cycle upgrades the pending poll to `.interactive` so it isn't downgraded to a silent one. Providers fetch concurrently; one failing doesn't block the other. Uses generation counters + a `PollLifecycle` guard so stale results from a cancelled cycle are never applied. Hidden providers are skipped entirely. Reusable `stop()` closes provider-owned child processes without disabling later polls; final `shutdown()` additionally makes those providers reject late work, and app termination waits for that cleanup before exiting.
- `AppState` (`@MainActor @Observable`) — provider states, hidden set, last-attempted vs. last-successful refresh times (a failed poll updates "attempted" but not "as of").
- `ThresholdNotifier` (actor) — fires once per (provider, window, threshold, reset-cycle) when percent remaining crosses below the threshold (default 20%, configurable); re-arms on new reset cycle; retries after failed delivery; stale providers never notify.
- `UsageClock` — injectable now/sleep for deterministic poller tests.
- Formatters are pure functions: `MenuBarTitleFormatter`, `CountdownFormatter` (relative under 24 h, weekday+time from 1 day up to 7 days out, calendar-day count + time beyond 7 days — e.g. `resets in 22 days 10:52 PM`, since a weekday name alone can't say which week a monthly reset lands in — "resetting..." when past), `tone(for:)` (normal / warning below threshold / critical below 5%, driven by five-hour, weekly, and optional monthly windows).
- `SettingsStore` — UserDefaults keys under `settings.*`: poll interval, threshold percent, per-provider visibility, launch-at-login flag, and optional non-secret OpenCode workspace ID. OpenCode visibility defaults to false; Claude and Codex remain true.

## Conventions and gotchas

- **TDD** (red–green–refactor) with Swift Testing; every behavior in `UsageCore` has a test. Views contain no logic — they render `AppState`/view models and call intents on the shell model.
- Swift 6 strict concurrency throughout: value types are `Sendable`, `UsagePoller`/`ThresholdNotifier` are actors, `AppState` is main-actor.
- Never commit real credentials or unsanitized captured payloads; fixtures in `Tests/Fixtures/` are sanitized. `docs/endpoints.md` records the discovered endpoint/keychain contracts and the evidence behind them.
- OpenCode parser changes must be backed by a sanitized observed fixture. Do not add speculative aliases, fallback regexes, local SQLite quota estimation, or browser support beyond Chrome without a new product decision.
- Do not add OAuth refresh, credential writes, or calls that could mutate CLI state — read-only access is a hard product constraint (see `docs/PLAN.md` non-goals). The only approved exception is invoking OpenAI's signed Codex desktop `app-server` for `initialize` / `initialized` / `account/rateLimits/read`; do not add any other app-server RPC.
- Feature branches only; never commit or push directly to `main`.
